# 1. Go for the backend services

Date: 2026-11-02 · Status: Accepted · Epic 1

## Context

The backend is a set of HTTP services: one handles bursts of concurrent booking traffic, the other serves reads. It has to be production-grade, and part of the point is learning how professional Go teams build services like this.

## Decision

Write all services in Go: `net/http` for routing, `log/slog` for logs, pgx for Postgres.

## Consequences

- \+ Goroutines and a fast runtime fit high-concurrency network services. Each service is a single static binary in a small image.
- \+ The standard library covers routing, JSON, testing, and the race detector, so there are few dependencies.
- − More boilerplate than frameworks in other languages (explicit errors, no ORM magic).
- Evaluation scripts for the AI extensions may be in Python. The services stay in Go.

**Reopen if:** never for existing services. A new service with very different needs (for example ML inference) could pick its own language.
